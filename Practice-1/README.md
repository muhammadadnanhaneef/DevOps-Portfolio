# Practice 1 – GitFlow Branching Strategy & Private Repository Setup

## 📌 Objective

The objective of this practice was to learn how to work with an existing project, manage source code using Git and GitHub, create a personal private repository, and implement a basic GitFlow branching strategy.

---

## 🚀 What I Practiced

During this practice, I worked through the following Git and GitHub workflow:

* Reviewed the project README file to understand the project structure and requirements.
* Selected and cloned an existing project repository.
* Created my own private GitHub repository.
* Uploaded the project to my personal repository.
* Managed the project using multiple Git branches.
* Implemented a basic GitFlow branching strategy.
* Practiced working with development, staging, and feature branches.
* Made changes in a feature branch.
* Learned the workflow of merging feature changes into the development branch through a Pull Request.
* Troubleshot Git-related issues encountered during the workflow.

---

## 🌿 GitFlow Branching Strategy

The following branches were created and used:

### `main`

The main branch represents the primary version of the project.

### `dev`

The development branch is used to combine and test completed development work.

### `stg`

The staging branch is used for testing and preparing changes before the final release.

### `feature/adnan-haneef`

The feature branch was used to develop and manage individual changes separately from the main development branches.

---

## 🔄 Basic Git Workflow

The workflow followed during this practice was:

```text
main
  │
  ├── dev
  │     │
  │     └── feature/adnan-haneef
  │
  └── stg
```

A typical development workflow was:

1. Clone the existing project repository.
2. Create a personal private GitHub repository.
3. Push the project to the new repository.
4. Create development and staging branches.
5. Create a feature branch for development work.
6. Make changes in the feature branch.
7. Push the feature branch to GitHub.
8. Create a Pull Request.
9. Merge the completed work into the development branch.
